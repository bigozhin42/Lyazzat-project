# PRD — Трекер задач сотрудников

## 1. Обзор продукта

**Название:** Трекер задач сотрудников  
**Тип:** Веб-приложение (single-page, без бэкенда)  
**Цель:** Отслеживать задачи сотрудников, фиксировать переносы сроков и понимать реальную длительность задач.

---

## 2. Роли пользователей

| Роль | Права |
|------|-------|
| Редактор (владелец) | Полный доступ: добавление / редактирование / удаление сотрудников и задач, перенос сроков, управление личным чек-листом |
| Наблюдатель | Только просмотр данных |

---

## 3. Архитектура и навигация

### Макет
- Одностраничное приложение с **боковым меню** (sidebar) слева и **основной областью** справа.
- Данные хранятся в `localStorage` браузера.

### Боковое меню
- Логотип / название в шапке.
- Раздел **«Навигация»**: ссылка на страницу Аналитики.
- Раздел **«Сотрудники»**: список имён с цветными аватарами. Красная точка рядом с именем — признак наличия переносов сроков.
- Кнопка **«Добавить»** внизу списка сотрудников.
- Раздел **«Я»** в самом низу сайдбара — личная зона владельца с ежедневным чек-листом.

---

## 4. Страницы

### 4.1 Аналитика (главная)

**Метрики (4 карточки):**
- Всего задач
- Важные задачи (кол-во и % от всех)
- Операционные задачи (кол-во и % от всех)
- Задачи с переносами (кол-во и %)

**Таблица «Соблюдение сроков»:**
- Строка на каждого сотрудника, отсортированная по уровню риска (от высокого к низкому).
- Колонки: Сотрудник, Задач всего, Важных, Операционных, Переносов, Оценка.
- Клик по строке → переход на страницу сотрудника.

**Логика оценки риска:**
| Условие | Уровень |
|---------|---------|
| ≥ 60% задач с переносами ИЛИ ≥ 3 переносов | Высокий — «Часто нарушает сроки» |
| ≥ 30% задач с переносами ИЛИ ≥ 2 переносов | Средний — «Иногда нарушает» |
| Остальные | Низкий — «Соблюдает сроки» |

---

### 4.2 Страница сотрудника

**Шапка:** аватар, имя, роль, сводные цифры (задач / важных / операционных / переносов).  
**Действия в шапке:** редактировать сотрудника, удалить, добавить задачу.

**Метрики (4 карточки):** аналогично аналитике, но только по данному сотруднику.

**Таблица задач:**

| Колонка | Описание |
|---------|----------|
| Задача | Название + описание |
| Тип | Важная / Операционка |
| Статус | В работе / Готово / Просрочено / Пауза |
| Начало | Дата начала |
| Исходный срок | Первоначальный дедлайн (перечёркнут при наличии переносов) |
| Переносов | Счётчик с цветовым алармом (0 — серый, 1 — оранжевый, 2 — тёмно-оранжевый, 3+ — красный) |
| Текущий срок | Актуальный дедлайн (красный при переносах) |
| Длительность | Кол-во дней от начала до текущего срока |
| Действия | Перенести срок / Редактировать / Удалить |

---

### 4.3 Личный чек-лист («Я»)

**Концепция:** ежедневный список задач для владельца. Каждый день — отдельный чек-лист.

**Навигация по дням:** стрелки «назад / вперёд» + кнопка «Сегодня».

**Логика задач:**
- Задача без срока, оставшаяся невыполненной, **автоматически переходит на следующий день** (метка «перенос», жёлтая полоса).
- Задача с указанным сроком **появляется в указанный день** (метка «запланировано», синяя полоса).
- Выполненные задачи остаются только в дне выполнения.

**Добавление задачи:**
- Текстовое поле + выбор даты (по умолчанию — текущий день) + кнопка «Добавить».
- Ввод через Enter.

**Отображение:**
- Прогресс-бар и счётчик «N из M выполнено».
- Секция «К выполнению» и секция «Выполнено».
- Галочка по клику переключает статус выполнения.
- Редактирование задачи: изменить текст или перенести срок.

---

## 5. Управление сотрудниками

### Добавление
- Поля: Имя и фамилия, Должность / роль, Цвет аватара (5 вариантов).

### Редактирование
- Те же поля, доступны со страницы сотрудника (иконка карандаша).

### Удаление
- С подтверждением. Удаляет сотрудника и все его задачи.

---

## 6. Управление задачами

### Добавление задачи
Поля:
- Название (обязательное)
- Описание
- Тип: Важная / Операционка
- Статус: В работе / Готово / Просрочено / Пауза
- Дата начала
- Плановый срок (обязательный)
- Заметки

### Редактирование задачи
- Все поля выше + исходный срок (первый дедлайн).

### Перенос срока
- Новая дата (не раньше текущего срока).
- Причина переноса (сохраняется в заметках).
- Счётчик переносов увеличивается на 1.
- История всех дат хранится.

### Удаление задачи
- С подтверждением.

---

## 7. Экспорт

- Кнопка **«CSV»** на странице аналитики.
- Формат: `Сотрудник; Роль; Задача; Тип; Статус; Начало; Исходный срок; Переносов; Текущий срок`.
- Кодировка UTF-8 с BOM (корректное открытие в Excel).

---

## 8. Хранение данных

- Все данные (сотрудники, задачи, чек-лист) сохраняются в `localStorage`.
- Ключ хранилища: `tt4_data`.
- Структура:

```json
{
  "employees": [
    {
      "id": "e1",
      "name": "Анна Петрова",
      "role": "Менеджер",
      "colorIdx": 0,
      "tasks": [
        {
          "id": "t1",
          "name": "Название задачи",
          "desc": "Описание",
          "type": "important | ops",
          "status": "active | done | overdue | paused",
          "start": "2025-06-01",
          "deadlines": ["2025-06-20", "2025-07-05"],
          "notes": "Заметки / причины переносов"

      "done": false,
      "createdDate": "2025-06-25",

    }
  ]

```

## 9. Дизайн-система

- **Стиль:** минималистичный, корпоративный, плоский (без теней и градиентов).
- **Цветовые метки аватаров:** синий, зелёный, фиолетовый, оранжевый, розовый.
- **Цветовая семантика:**
  - Синий — статус «В работе», операционные задачи
  - Зелёный — статус «Готово», соблюдение сроков
  - Красный — просрочено, переносы, высокий риск
  - Оранжевый / янтарный — средний риск, 1–2 переноса
  - Серый — нейтральный статус, 0 переносов
- **Адаптация к тёмной теме:** все цвета через CSS-переменные.
